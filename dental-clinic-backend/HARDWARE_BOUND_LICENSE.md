# نظام الترخيص المرتبط بالعتاد (Hardware-Bound License)

## نظرة عامة

نظام ترخيص جديد يحمي تطبيق عيادة الأسنان عن طريق ربط الترخيص بالعتاد الصلب للكمبيوتر (Hardware Binding). هذا النظام يمنع نسخ التطبيق إلى كمبيوتر آخر دون ترخيص جديد.

## كيف يعمل

### 1. آلية الحماية
- كل كمبيوتر له "بصمة عتاد" فريدة (Hardware Fingerprint)
- مفتاح الترخيص يتم إنشاؤه بناءً على هذه البصمة
- إذا تم نسخ مجلد التطبيق إلى كمبيوتر آخر، تتغير البصمة
- النظام يكتشف التغيير ويمنع الوصول تلقائياً

### 2. المزايا
- **أمان عالي**: لا يمكن نقل الترخيص بين الأجهزة
- **عمل أوفلان**: لا يحتاج إلى اتصال بالإنترنت للتحقق
- **سهولة الاستخدام**: مرة واحدة فقط عند التثبيت
- **منع النسخ**: يحمي من النسخ غير القانوني

## متطلبات النظام

### 1. تثبيت الحزمة
```bash
npm install node-machine-id
```

### 2. متغيرات البيئة (.env)
```env
# مفتاح سري لتوليد بصمة العتاد
HARDWARE_SALT=your-secret-salt-string-here

# المفاتيح الموجودة مسبقاً
JWT_PRIVATE_KEY=...
JWT_PUBLIC_KEY=...
```

## استخدام النظام

### 1. توليد مفتاح ترخيص مرتبط بالعتاد
```bash
npm run license:generate-hardware-key
```

سيظهر ناتج مثل:
```
✅ Generated Hardware-Bound License Key:
=======================================
HARDWARE-ABC123DEF456GHI789JKL012MNO345-5F3759DF
=======================================
```

### 2. تفعيل الترخيص
1. أدخل مفتاح الترخيص في شاشة تفعيل التطبيق
2. النظام يتحقق من مطابقة البصمة مع العتاد الحالي
3. إذا نجح التحقق، يتم التفعيل
4. يتم تخزين بصمة العتاد في قاعدة البيانات

### 3. التحقق التلقائي
- عند كل تشغيل للتطبيق، النظام يتحقق من مطابقة بصمة العتاد
- إذا تم نسخ المجلد إلى كمبيوتر آخر، تختلف البصمة
- النظام يمنع الوصول ويظهر رسالة خطأ

## صيغة مفتاح الترخيص

```
HARDWARE-{HASH}-{TIMESTAMP}
```

**مثال:**
```
HARDWARE-ABC123DEF456GHI789JKL012MNO345-5F3759DF
```

- `HARDWARE`: مؤشر أن هذا ترخيص مرتبط بالعتاد
- `ABC123...`: تجزئة تشفيرية مبنية على بصمة العتاد والمفتاح السري
- `5F3759DF`: الطابع الزمني بالهيكساديسيمال

## توليد المفاتيح للعملاء

### للاستخدام الداخلي (المطورين)
```bash
# توليد مفتاح تجريبي
npm run license:generate-hardware-key
```

### للعملاء (البيع أوفلان)
1. قم بتشغيل الأمر على كمبيوتر العميل:
```bash
npm run license:generate-hardware-key
```

2. احفظ المفتاح الذي تم توليده
3. سلم المفتاح للعميل (ورقياً أو ملف نصي)

## آلية التحقق

### 1. عند التفعيل
```javascript
const isValid = hardwareIdService.validateLicenseKey(licenseKey, hardwareFingerprint);
```

### 2. عند كل تشغيل
```javascript
const currentFingerprint = await hardwareIdService.generateHardwareFingerprint();
const storedFingerprint = licenseRecord.hardware_fingerprint;

if (currentFingerprint !== storedFingerprint) {
  // منع الوصول - نسخة غير مرخصة
}
```

## تدفق العمل

### تثبيت جديد
1. العميل يثبت التطبيق
2. النظام يعرض شاشة التفعيل
3. العميل يدخل المفتاح المرتبط بالعتاد
4. النظام يتحقق ويخزن بصمة العتاد
5. التطبيق يعمل بشكل طبيعي

### نسخ غير مصرح به
1. شخص ينسخ مجلد التطبيق إلى كمبيوتر آخر
2. بصمة العتاد الجديدة تختلف عن المخزنة
3. عند التشغيل، النظام يكتشف الاختلاف
4. يمنع الوصول ويعرض رسالة "ترخيص غير صالح"

## استكشاف الأخطاء

### مشكلة: "Cannot retrieve machine ID"
**الحل:**
```bash
# تشغيل كمسؤول (Admin)
npm run license:generate-hardware-key
```

### مشكلة: المفتاح لا يعمل
**التحقق:**
```bash
node scripts/generate-hardware-key.mjs --validate HARDWARE-ABC123...
```

### مشكلة: نظام التشغيل غير مدعوم
**الحل البديل:** النظام يستخدم معلومات النظام كبديل (Hostname, CPU, Memory)

## الأسئلة الشائعة

### 1. هل يمكن نقل الترخيص إلى كمبيوتر آخر؟
**لا.** كل مفتاح مرتبط بجهاز محدد.

### 2. ماذا يحدث إذا تغيرت مكونات العتاد؟
- التغييرات الطفيفة (RAM، HDD) لا تؤثر
- التغييرات الرئيسية (Motherboard، CPU) قد تؤدي إلى تعطيل الترخيص
- في هذه الحالة، تحتاج إلى مفتاح جديد

### 3. هل النظام يعمل بدون إنترنت؟
**نعم.** التحقق محلي بالكامل.

### 4. كيف يمكنني إعادة تفعيل على نفس الجهاز؟
باستخدام نفس المفتاح (مخزن بشكل آمن).

### 5. ماذا عن النسخ الاحتياطي؟
- بيانات الترخيص مخزنة في قاعدة البيانات
- عند استعادة النسخ الاحتياطي على نفس الجهاز، يعمل بشكل طبيعي
- على جهاز مختلف، لا يعمل

## أمان النظام

### 1. التشفير
- SHA-256 لتجزئة بصمة العتاد
- مفتاح سري (Salt) لإضافة تعقيد
- طابع زمني لمنع إعادة الاستخدام

### 2. الحماية
- لا يمكن عكس المفتاح إلى بصمة العتاد
- كل مفتاح صالح لمدة 24 ساعة فقط للتوليد
- التحقق المستمر عند التشغيل
