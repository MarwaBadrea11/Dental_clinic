# نظام إدارة الترخيص - SmileFix Dental Clinic

## نظرة عامة
نظام ترخيص متكامل يحمي تطبيق عيادة الأسنان ويضمن تشغيله فقط عند الحصول على ترخيص صالح. يعتمد النظام على التحقق الدوري من سيرفر الترخيص الرئيسي.

## المكونات

### 1. قاعدة البيانات
- جدول `license_info` لتخزين معلومات الترخيص
- الحقول: `license_key`, `status`, `activated_at`, `last_verified_at`, إلخ.

### 2. الباك إند (Fastify)
- وحدة `src/modules/license/`:
  - `license.routes.js`: واجهات API للتفعيل والتحقق
  - `license.controller.js`: معالجة طلبات الترخيص
  - `license.service.js`: منطق الترخيص والتحقق من السيرفر الرئيسي
  - `license.repository.js`: إدارة بيانات قاعدة البيانات

- Middleware `src/middleware/licenseGuard.js`:
  - يحمي جميع واجهات API (باستثناء المسارات العامة)
  - يتحقق من حالة الترخيص قبل تنفيذ أي طلب
  - يقوم بالتحقق الدوري في الخلفية كل 7 أيام

### 3. الفرونت إند (React)
- صفحة `src/pages/ActivateAppPage.tsx`:
  - واجهة تفعيل النظام باللغتين العربية والإنجليزية
  - إدخال مفتاح الترخيص وتفاصيل العميل

- حماية المسارات في `src/routes/AppRouter.tsx`:
  - يتحقق من حالة الترخيص عند تحميل التطبيق
  - يوجه المستخدم إلى صفحة التفعيل إذا كان الترخيص غير نشط

## واجهات API

### 1. تفعيل الترخيص
```
POST /api/v1/license/activate
```
```json
{
  "licenseKey": "XXXXX-XXXXX-XXXXX-XXXXX",
  "customerName": "اسم العيادة",
  "customerEmail": "clinic@example.com"
}
```

### 2. التحقق من حالة الترخيص
```
GET /api/v1/license/status
```

### 3. صحة النظام (health check)
```
GET /api/v1/license/health
```

## حالات الترخيص

1. **PENDING**: النظام غير مفعل (الحالة الافتراضية)
2. **ACTIVE**: النظام مفعل ويعمل بشكل صحيح
3. **REVOKED**: الترخيص ملغي (لم يعد صالحاً)
4. **EXPIRED**: انتهت صلاحية الترخيص

## آلية الحماية

### 1. التحقق المبدئي
- عند كل طلب API (باستثناء المسارات العامة)
- يرفض الطلب برسالة 403 إذا كان الترخيص غير نشط

### 2. التحقق الدوري
- كل 7 أيام يتحقق من سيرفر الترخيص الرئيسي
- إذا فشل التحقق، يتم إلغاء الترخيص محلياً

### 3. فترة السماح (Grace Period)
- 7 أيام للتحقق من السيرفر الرئيسي
- بعدها يتوقف النظام إذا لم يتم التحقق

## تدفق العمل

### تفعيل النظام لأول مرة:
1. المستخدم يدخل إلى التطبيق
2. النظام يتحقق من حالة الترخيص (PENDING)
3. يتم توجيه المستخدم إلى صفحة التفعيل
4. المستخدم يدخل مفتاح الترخيص
5. النظام يتحقق من السيرفر الرئيسي
6. إذا نجح التحقق، يتم تفعيل النظام
7. يتم توجيه المستخدم إلى لوحة التحكم

### التشغيل العادي:
1. النظام يتحقق من الترخيص عند كل دخول
2. إذا كان الترخيص ACTIVE، يسمح بالوصول
3. كل 7 أيام يتحقق من السيرفر الرئيسي
4. إذا فشل التحقق، يرسل تنبيه ويلغي الترخيص

## التخصيص

### سيرفر الترخيص الرئيسي
يمكن تخصيص عنوان سيرفر الترخيص عبر متغير البيئة:
```env
MASTER_LICENSE_SERVER_URL=https://your-license-server.com/api/validate
```

### فترة التحقق
يمكن تغيير فترات التحقق:
```env
LICENSE_GRACE_PERIOD_DAYS=14  # زيادة فترة السماح إلى 14 يوم
LICENSE_BACKGROUND_CHECK_INTERVAL=43200  # التحقق كل 12 ساعة
```

## الأمان

### الحماية من النسخ
- كل تثبيت له بصمة فريدة (Server Fingerprint)
- لا يمكن استخدام الترخيص على أكثر من جهاز

### الاتصال الآمن
- جميع الاتصالات مع سيرفر الترخيص عبر HTTPS
- بيانات الترخيص مشفرة في قاعدة البيانات

## استكشاف الأخطاء

### مشكلة: "License Inactive"
1. تحقق من اتصال الإنترنت
2. تحقق من مفتاح الترخيص
3. تحقق من اتصال سيرفر الترخيص
4. تواصل مع الدعم الفني

### مشكلة: "Cannot contact license server"
1. تحقق من إعدادات الشبكة
2. تحقق من جدار الحماية
3. تأكد من صحة عنوان سيرفر الترخيص

## تطوير محلي

### وضع التطوير
في وضع التطوير، النظام لا يتطلب اتصال بسيرفر الترخيص:
- يستخدم مفتاح ترخيص افتراضي
- يعتبر الترخيص ACTIVE تلقائياً

### اختبار النظام
```bash
# اختبار حالة الترخيص
curl http://localhost:3000/api/v1/license/status

# اختبار التفعيل
curl -X POST http://localhost:3000/api/v1/license/activate \
  -H "Content-Type: application/json" \
  -d '{"licenseKey":"TEST-LICENSE-KEY"}'
```
